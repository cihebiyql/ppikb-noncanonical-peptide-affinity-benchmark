# PepInter 全模型训练路线与已完成范围

已完成的是固定回归监督骨干、原生 2304→1152→1 分类头及 FocalLoss 的十种子组件基准。十个独立新分类头、二十个候选权重、验证选参及共同测试预测均已完成并在本地逐文件校验。它不代替全模型训练。后续完整模型候选与必要优化器/RNG文件将按 root 的 E:/research-artifacts/peptide-four-task-benchmark-20261022/pepinter-full-native 本地固定卷政策保存：自有预算195GiB，每次传输后仍保留50GiB可用空间，逐成员绝对路径/字节/SHA由任务根manifest引用，不移动旧D盘资产。远端 /data 本次实际可用7.652TB，训练前还需实时复核。

公开代码的 train_cls.yaml 设置：bf16-mixed、批量 24、5 轮、学习率 1e-4、梯度裁剪 1.0。BaseLightningModule.configure_optimizers 对 self.parameters() 建立 AdamW，默认权重衰减 0.01、warmup_ratio 0.05；按每轮步数和总轮数构建逐步线性预热/衰减。原生模型 576,293,761 个参数全部可训练。公开配置未启用本轮探针所使用的梯度检查点选项。

原始分类配置指向 energy 阶段检查点。已有官方记录 18604811 的元数据只列 classification 和 regression 两个监督检查点，没有 energy 或 MLM 检查点。本轮使用 regression 检查点初始化骨干，因此后续即使完成全参数训练，也须标记监督初始化暴露条件，并按已发布训练记录检查相同输入、来源及同源重叠，不能称为完全未暴露泛化。

已有 CPU FP32 单步真实成功：最短 TRAIN 输入 48 token，全参数张量均有有限梯度，AdamW 更新成功。该诊断未执行完整训练日程，不能证明 GPU 混合精度、长输入或批量 24 的可行性。

新 GPU 门以按原样 TRAIN 观测的组合长度选择的最短与全局最长输入分别形成 48 和 991 token，CPU 原生配对 tokenizer 已实际核对，无截断。两项均为原架构、全参数、原 FocalLoss、AdamW、bf16 autocast，显式启用原模型支持的梯度检查点，批量 1。每项独立 12 GiB GPU 上限和 1,200 秒时限，仍需额外 6 GiB 其他任务增长余量。由唯一 GPU 调度器按实时容量准入；短步实际成功之后才运行长步。OOM 保留，不切换为 LoRA 或冻结骨干。

短、长单步成功只支持对应输入长度的训练能力。下一步应先记录实际单步耗时、优化器状态峰值和输入长度分布，再冻结一个保留原全参数、FocalLoss、五轮及原学习率日程的共同数据完整训练协议。若批量 24 放不下，可单独预声明批量 1 加梯度累积的资源适配，明确随机数、优化器步数与数值行为差异，不能当作原批量设置未变。先进行一个有完整验证选参和测试的真实种子，再按已授权十种子推进；不把单步或局部训练计作完整种子。

当前实际 GPU 门状态以唯一资源调度器收据为准；本目录 protocol-v2 index 和 descriptor 通过完整接口/引用 SHA/CPU shape 预检，只代表准备完成。
