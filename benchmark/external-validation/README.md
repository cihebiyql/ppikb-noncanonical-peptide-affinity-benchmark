## 分子输入如何得到

SH2 和 Kliche 原表没有 SMILES，但逐条给出实际残基、pS/pT/pY 位点及端基。`convert_explicit_measured_entities.py` 仅把这 **75 个原有测量实体**转换为化学图，没有产生新候选、进行设计或亲和力优化。

- 保留 N-acetyl、C-amide 或原注释的 COO−；不能将有封端的分子写成游离端基肽。
- 磷酸接入原注释指定残基的侧链氧，核对实际位置和残基类型；采用中性磷酸的显式表示约定，不推断溶液酸碱分布。
- 逐行核对元素计数、化学价、原有立体标签、磷原子数、端基电荷、单组分及 SMILES 往返一致性。
- 8 条 Kliche 保留原有结合位点条件或构建体边界冲突，单列敏感性；没有覆盖原警示。

Node1 已有 RDKit 2024.03.2 完成 75 条转换，1 CPU、nice 19、0 GPU，耗时 **3.14 秒**，75 成功、0 失败，进程已退出。全库化学审核同样 1 CPU / 0 GPU，耗时 **81.53 秒**，21,845 条解析失败 **0**。初次运行中的本地 Windows/POSIX 路径拼接失败收据仍保留在 `chemistry-format-conversion/`，随后版本已修复。

## 金标与调参隔离

- 模型只读取 `inputs/blind-inputs-with-certified-format-conversion.jsonl`。
- 原测量与不确定性保存在 `gold/posttraining-gold.jsonl`，用于全部模型/十种子的超参数冻结后的评分。
- 根据 Kd、SEM 或均值派生的质量旗标已从模型输入中去除，原旗标留在 gold/provenance，避免给模型间接透露结果大小。
- 这些公开标签在此前项目审计中已经被查看，所以这里是**回顾性的独立来源外部评价**，不能称全新前瞻盲测。单一共享账户采用目录和程序数据流隔离，没有声称操作系统级访问隔离。
- 评价保留全部 75 个推理候选，另报 67/8 的既定分层。某模型无法接受输入须保留失败记录和原因，不能在看到误差后静默删样本。误差、相关性、来源/PTM 类型分层及全部 10 种子预测均由后续模型运行产生。

## 复跑和冻结

`prepare_external_audit.py` 负责原表读取、来源匹配和无标签输入；`run_format_conversion.py` 与 `convert_explicit_measured_entities.py` 保留格式转换命令和资源限额；`run_all_ppikb_audit.py` 与 `audit_all_ppikb_chemistry_cpu.py` 负责全库图去重；`finalize_external_inputs.py` 合并已验证格式；`freeze_acceptance.py` 在所有门槛通过后生成不可覆盖的 v1 接受清单。

重跑须复制到新版本目录并采用新的远端 run 目录，保持本版清单引用的输入、金标、审计文件和 SHA 不变。后续新来源或修正以 v2 sidecar 追加，不覆盖本版。
