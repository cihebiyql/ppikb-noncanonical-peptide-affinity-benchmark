# 论文复现流程与验收标准 v1

版本：1.0。适用范围：本工作台新增论文登记、复现任务及既有结果整理。规范从本次制定起使用；既有原始记录、任务编号、权限、期限和失败证据继续保留。

## 1. 统一入口与目录

网页入口：[复现资料库](http://127.0.0.1:4318/?collection=reproductions)。原62篇登记位于 `复现/campaign.json`，概览读取 `复现/汇总表工作文件/merged_rows.json`。新增批次使用 `复现/batches/<批次>/campaign.json` 与 `summary-rows.json`，由 `复现/batches/index.json` 引用；重复论文通过 `linked_task_ids` 保留同一任务。网页实现与资料分类见 `paper-lumen/docs/REPRODUCTION-LIBRARY.md`。

```text
复现/
  campaign.json
  规范/                         本标准及可复制模板
  papers/<稳定任务编号>/
    metadata.json               论文身份、DOI、正式版与预印本对应关系
    analysis.md                 数据、创新、验证设计与原文证据
    code-audit.md               代码、依赖、许可证与模型完整性
    reproduction-plan.md        本轮目标与合同的可读说明
    status.json                 当前状态，保留原计时与历史字段
    events.jsonl                追加事件，不覆盖过去失败
    results.md                  本轮实际结果、对照、差异和未完成原因
    assets/                     数据、权重或其可追溯清单
    repo/ 或 repositories/      冻结源码；原件不直接修改
    runs/<run_id>/
      task-contract.json        启动前冻结的运行合同
      result-record.json        本轮机器可读结果
      logs/                     原始标准输出、错误与过程日志
      artifacts/                结果、收据及必要输入输出清单
```

沿用已有目录时不强制搬迁或复制大文件；在清单中记录真实位置、是否本地可读及校验值。网页能打开文件、Git 仓库存在或 PDF 已下载，均不等于复现完成。新增论文先去重并登记稳定编号，再建立资料目录；同一论文的正式版和预印本关联至同一身份，不重复计为两篇。

## 2. 固定工作流

| 阶段 | 必做事项 | 可以结束于 |
|---|---|---|
| 登记 | 核对标题、DOI、首次在线日期、论文类型、版本和 PDF SHA256；记录本轮选文范围 | registered |
| 原文与资产审计 | 提取数据与创新证据；核对代码、依赖、权重、配置和许可；分清主实现与依赖 | assets_only / static_audit |
| 冻结合同 | 明确论文表图/端点、输入范围、指标公式、容差、资源、期限和停止条件 | ready 或 blocked |
| 有界执行 | 在隔离环境运行合同范围；记录真实进程、日志、终态和产物 | smoke / component / 更高层级 |
| 对照与验收 | 逐端点核对本轮数值、论文数值、分母、单位和差异；复核证据及进程退出 | succeeded / partial / failed / blocked 等 |
| 归档与展示 | 保存结果与差异，更新可读报告和可追溯概览；保留历史 | 已验收记录 |

用户已授权范围内的普通读取、隔离准备、公开资产下载和低风险可逆操作自动推进。缺少科学输入、资源或权限时明确阻塞点；不要把每个阶段变成人工审批。超出既有授权或安全边界的任务不启动。

## 3. 原文、数据和创新证据

- **身份与版本**：DOI 规范化、正式发表状态、期刊、出版日期和版本分别记录。预印本不得标成正式出版 PDF；PDF 文件记录 SHA256 和取得来源。期刊指标需同时记录指标年份与来源，不能由期刊名推断。
- **筛选口径**：若本批要求“蛋白质、严格纯计算、无新增湿实验”，记录是否符合及原文依据；不能仅凭摘要没有实验描述就认定符合。无法判断标记 unknown。
- **数据**：记录名称、版本/日期、来源、许可、规模和统计单位；冻结 train/validation/test 与排除规则。记录输入清单或拆分文件 hash、预处理、同源/实体重叠及泄漏检查。公开来源无法访问不等于数据不存在。
- **创新**：区分作者声称与本轮归纳，给出原文页码、节、表图或已有分析路径。不得用宣传性表述代替已验证增益。
- **证据类型**：`source_fact` 为可定位的原始事实；`synthesis` 为基于证据的归纳；`unknown` 为尚未核实。未知写明缺什么证据，不补成默认值。

## 4. 代码、模型与环境完整性

主代码记录官方来源、真实 commit 或归档 SHA256、是否完整 checkout、子模块/LFS 状态、依赖锁定和许可证。仓库对象库、源码片段、配套依赖与作者主实现分别记录，不合并宣称完整。安装前检查 README、入口、依赖与安装脚本；仓库内容按未信任输入处理。

权重记录用途、版本、文件 SHA256、配置/词表/特征资源、适用折数或任务覆盖范围及许可证。完整性取值统一为 `complete / partial / missing / unknown / not_applicable`，并说明相对于哪个目标。“不适用”须有依据；缺权重不写为不适用。若仅完成静态检查，不宣称模型可成功推理。

环境按论文或单轮运行隔离，保留 Python/系统/驱动/框架版本、锁定清单及环境文件路径。不得更改共享环境。原始源码保持冻结；修复放在任务专用副本，保存 diff、原因及对结果的可能影响。

同时核对作者顶层启动入口的数值策略：参数与输入 dtype、autocast、矩阵乘法精度、TF32、确定性和随机种子。单独调用模型类时也要继承适用设置，不能只复制模型超参数。可在 `environment.numerical_policy` 记录作者值、本轮实际值、设置时机与证据；未知或不适用明确说明。此字段为新增记录约定，不追溯改写已冻结合同。

## 5. 启动前冻结任务合同

复制 `task-contract.template.json` 至 `runs/<run_id>/task-contract.json`，填写后将 `is_template` 设为 `false`，状态从 `draft` 改为 `frozen`，记录文件 SHA256。最低必填内容为：

1. 论文身份、稳定任务编号、唯一 run_id 和本轮授权依据。
2. 明确的表图/端点与科学范围；全数据、子集、单组件、作者输出重算分别标记。
3. 输入与拆分、代码版本、权重及配置，以及资产完整性依据。
4. 每个端点的论文基准数值/来源、指标定义、分母、单位、统计重复、比较端点和预注册容差；没有可靠基准时只能标记暂不可比较。
5. 真实启动命令、工作目录、隔离环境、seed 策略和资源预算。
6. 首次实质处理时间、各适用截止时间、有效截止、timeout 和停止条件。

运行后发现比较口径错误，可新增合同修订并保存旧版、修订原因与时间；不能在看到结果后静默放宽容差或挑选最有利端点。模型检查点、均值/中位数、最后一步/最优步、微平均/宏平均、分母及单位不一致时，先明确不可直接比较，不强行计算“复现误差”。

文件哈希以落盘后的实际字节计算并在执行端复核；Windows CRLF 与 LF 是不同字节，不能用内存中规范化后的文本替代文件 SHA。执行前发现不一致先停止启动，保留门槛失败收据，定位传输或清单问题；不通过删除哈希校验继续。

## 6. 时间与资源规则

每篇首次实质处理起最多 **10 小时墙钟时间**，包含分析、准备、下载、安装、等待与运行；失败、重试、阶段切换和新建 batch 均不重置。若审计发现更早的关联准备时间，保留原时间并采用所有适用截止的最早值。运行 timeout 不得超过剩余有效期限。

**既有 62 篇的原执行窗口已到期。** 新规范、资料补齐、网页接入或重新编号不能恢复其科学执行。其后可继续整理既有结果、修正事实与保全文件；新的科学执行必须有明确的新目标和适用授权，保留与旧合同的关联，且不得用于绕过旧期限、平台拒绝或其他限制。新论文去重后才获新任务编号。

资源预算按单任务合同和当时适用规则填写，不把历史单篇 GPU 编号、CPU 数或例外门限推广为全局许可。启动前核对真实 hostname、存储、权限、CPU/GPU 计算进程、占用、内存和 I/O 压力，记录探测时间与收据。显存空余本身不能证明 GPU 可用；不抢占其他任务，不终止他人进程。

采用有界进程控制：Linux 记录 PID/PGID 并约束整组；Windows 记录 PID 及适用的 Job Object/进程树控制。记录 timeout、线程、worker、内存和 GPU 限制。观察超时先核对原进程，不盲目重启；结束后验证自有进程树退出、exit code、日志和产物。平台不适用的字段写 null 并解释，不伪造 PGID。

最小试跑应覆盖本轮实际评测接口和结果保存：验证返回结构、单位、有限数值及序列化，避免只测预测入口而遗漏评分链。若预测已全部保存而评分失败，保留原预测、失败终态和 hash；另行冻结仅评分的续算合同，绑定相同预测与参考，不重生或挑选样本。联合结果须链接每阶段的合同、真实退出码和原始产物，不能把父阶段失败改成成功。

## 7. 科学范围与受限任务

允许推进既有授权内的一般预测、聚类、解释性、质量评估以及明确非危险公开数据上的算法基准。涉及危险生物功能增强、毒素、病原体或病毒适应度等风险目标的操作性执行不开展；序列生成、功能/亲和力优化等任务应先完成适用的范围核对，不因“纯计算”免除边界检查。

平台已拒绝的科学工作流保留拒绝与未完成记录，不通过换代理、翻译、拆分、重命名或新 batch 重试。可整理已有行政记录与结果边界，不能以补齐表格为由恢复受限科学内容。

## 8. 层级、状态与结果比较

复现层级描述证据种类，**不是必须逐级通过的排行榜**；层级与进程状态、科学范围分开存储。没有独立训练的工作也可能完成适用论文目标，但必须满足其全文端点。

| reproduction_level | 可以证明 | 不由此证明 |
|---|---|---|
| registered | 论文身份已登记 | 已取得资产或运行 |
| assets_only | 对应资料已取得并有清单 | 代码或模型可执行 |
| static_audit | 静态代码/资产审计已完成 | 运行正确或数值一致 |
| smoke | 最小输入成功跑通指定入口 | 主文指标、完整数据或训练 |
| component | 明确组件或子集得到可核对结果 | 全流程或整篇结论 |
| published_output_reanalysis | 对作者发布输出重算指定指标 | 独立推理、重新训练或重新采样 |
| independent_inference | 本轮从冻结输入和权重独立生成预测 | 训练成功或全文目标全部完成 |
| training | 本轮训练有可审计日志、检查点和验证 | 论文全部实验、消融及结论 |
| full_paper | 全部约定的论文必要端点已匹配并通过验收 | 超出原论文证据范围的结论 |

`lifecycle_status` 使用 `registered / ready / running / succeeded / partial / failed / blocked / not_run / expired / restricted`。`succeeded` 仅表示本合同目标通过，不自动等于 `full_paper`。`scope_coverage` 使用 `full / partial_subset / component_only / published_outputs_only / not_evaluated`。

每个比较端点保留论文值、本轮值、基线、单位、分母、计算方法、绝对/相对差异和通过与否。零分母、端点不等价、缺基准或未计算时相应数值为 null，并给出原因。不得以 0 代替未知；拒绝在运行前发生时不记录为算法失败；只校验归档 hash 不记录为数值复现。

## 9. 验收与交付

逐篇可读报告使用 `逐篇复现记录.template.md`，机器记录使用 `result-record.template.json`。结果记录绑定合同 SHA256；输入、日志与产物可追溯到真实路径。机器校验检查必填、枚举、时间、hash、端点和证据一致性；校验通过不替代科学判断。

| 验收项 | 通过条件 |
|---|---|
| 身份 | DOI/版本可定位，PDF hash 与登记一致，重复论文已合并 |
| 资产 | 数据拆分、代码 commit、模型/配置完整性已逐项说明 |
| 合同 | 目标、容差、资源和期限在执行前冻结，修订有历史 |
| 运行 | 命令、环境、host、seed、进程、日志、exit 与退出检查可审计 |
| 比较 | 单位/分母/检查点等价；所有必要端点均有结果或明确缺失原因 |
| 声明 | 实际层级、范围和结论相符，不把 smoke/作者输出当独立推理或训练 |
| 完整复现 | 全文必要目标已列清且全部验收，无遗漏的必需结果；复核为 accepted |
| 保全 | 既有失败、未知、限制和旧期限保留，原件未被结果摘要覆盖 |

review 取 `pending / accepted / needs_revision`。可以由同一执行者作基本复核，复杂关键结论适用时采用独立复核；不强制每个小任务额外审批。未通过的项目可完整归档为部分结果或阻塞，但不能标为整篇成功。网页概览和汇总表从已验收记录更新，并保留证据路径；不要靠修改摘要掩盖原始收据的差异。

## 10. 模板填写约定

模板中的 null、空数组和说明文字是待填项，不代表真实结论。`is_template=true` 的文件不能作为运行放行或成果验收依据。实际记录中的未知保留 null，并通过对应 `notes` 或 `reason` 说明；实测数值使用 JSON number。

模板字段的 `path` 可以为本地或远端真实位置，`location` 标记 local/remote；web 可访问性单独记录。`evidence_paths` 指向已有原文、审计、收据或日志。后续自动化只追加字段或进行有记录的版本迁移，不覆盖旧 62 篇的原始状态字段。

校验器为同目录的 `validate_reproduction.py`，仅使用 Python 标准库，不运行合同命令或模型：

```text
python validate_reproduction.py --contract task-contract.template.json --result result-record.template.json --allow-template
python validate_reproduction.py --contract <实际合同路径> --check-files
python validate_reproduction.py --contract <实际合同路径> --result <实际结果路径> --check-files
```

CLI 输出 JSON，通过返回 0，未通过返回 2。`--at <带时区ISO时间>` 仅用于明确时点的审计与测试；实际启动应使用默认当前时间，不能靠回拨时间获得运行放行。`--allow-template` 只检查模板结构，`valid_for_execution` 和 `valid_for_acceptance` 始终为 false。实际合同只有范围标记 `safety_assessment=allowed`、限制检查明确为 false、期限和其他必填校验通过时才可得到执行放行。

带 `--result` 时检查的是结果归档，可归档已到期或未运行的 blocked 记录，且不会获得执行放行。`--check-files` 核对本地引用及适用的成对 SHA256；远端路径记入 `files_skipped`，不能宣称已经完成本地文件/hash 校验。字段为空或仅有静态声明仍需按实际证据保留未知，机器校验不能代替人工科学判断。

## 附录：用户明确追加执行预算的例外

用户高优先级指令明确授权“允许新增2小时预算并继续运行”时，可在新合同追加 `timing.user_authorized_execution_window`。原 `first_substantive_started_at`、`earliest_associated_preparation_at`、`original_deadline_at` 及 `prior_window_expired=true` 必须保留；模板、重试和代理自行推断均不能触发该例外。

追加字段为 `run_id`、`authorization_path`、`authorization_sha256`、`started_at`、`deadline_at`、`wall_clock_cap_hours=2`。本地授权 JSON 收据使用 `schema=paper-reproduction.explicit-user-window-override.v1`，记录相同任务/阶段身份、`authority=direct_user_message`、上述原文 `user_message`、真实 `authorized_at`、`wall_clock_cap_hours=2`、原 `previous_deadline_at`，并冻结与合同完全一致的 `started_at` 和 `deadline_at`。授权必须晚于或等于旧期限，且早于或等于本次窗口开始；合同必须在授权后冻结。不同阶段可以分别绑定收据，但必须共享同一用户授权的窗口，不能按阶段重新追加两小时。

校验器无论是否启用 `--check-files` 都实际读取并核对本地授权收据及 SHA256。有效期限严格为 `min(started_at + 2小时, deadline_at)`；同一收据不能通过修改阶段身份或窗口起止复用。实际运行仍须晚于合同冻结及本次窗口开始，并受剩余时间和原资源、范围、安全及平台限制约束。到期记录继续保留，追加授权不改变旧运行历史，也不允许自动重启旧任务。
